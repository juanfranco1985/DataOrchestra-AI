# Decisiones de diseño

## Paleta utilizada

- Fondo principal: azul muy oscuro y grafito.
- Acento principal: cyan para tecnología, datos y llamadas a la acción.
- Acento secundario: verde suave para confianza, validación y controles aprobados.
- Acento puntual: ámbar para estado de revisión, alertas y piloto controlado.
- Texto: blanco y grises fríos para legibilidad.

## Justificación del estilo visual

La web busca transmitir seriedad, método y claridad. Se eligió una estética oscura, sobria y técnica, con tarjetas de borde fino, visuales de datos y una composición limpia. El objetivo es parecer una consultora tecnológica especializada, no una plantilla genérica de IA.

## Decisiones de tono

El tono es directo y prudente. Se evita prometer resultados, automatización total o escalamiento inmediato. La comunicación se orienta a PyMEs que necesitan entender mejor sus datos sin iniciar todavía un proyecto tecnológico grande.

## Por qué no se presenta como SaaS

El estado real del proyecto es v2.0 - Primer Piloto Real Controlado. Todavía faltan validación con clientes reales, operación productiva completa, contrato formal, interfaz interna profesional y proceso escalable. Presentarlo como SaaS generaría una expectativa incorrecta.

## Por qué se destaca revisión humana

La revisión humana es una parte central del flujo. El sistema genera métricas, alertas y recomendaciones, pero el informe no se entrega automáticamente. Esto reduce riesgos, mejora el criterio comercial y mantiene responsabilidad sobre lo que recibe el cliente.

## Por qué se habla de piloto controlado

La etapa de piloto permite validar si el diagnóstico aporta valor real antes de sumar complejidad técnica o comercial. También permite medir calidad de datos, esfuerzo operativo, claridad del informe y disposición del cliente a continuar.
